# Вместе — как запустить

Ты никогда не писал код. Ничего страшного: здесь всё уже написано, тебе нужно
только запустить. Делай по шагам, ничего не пропускай.

---

## Шаг 1. Установить Node.js

1. Открой https://nodejs.org
2. Скачай версию **LTS** (большая зелёная кнопка слева).
3. Установи как обычную программу — везде «Далее».

Проверка: открой **Терминал** (на Windows — «PowerShell», найди через поиск в
меню Пуск) и напиши:

```
node --version
```

Если появилось что-то вроде `v22.x.x` — готово.

---

## Шаг 2. Запустить у себя на компьютере

В терминале перейди в папку проекта. Проще всего: набери `cd ` (с пробелом),
потом перетащи папку `vmeste` мышкой прямо в окно терминала и нажми Enter.

Дальше две команды:

```
npm install
npm start
```

Появится строчка `Вместе — сервер запущен: http://localhost:3000`.
Открой этот адрес в браузере. Всё работает.

Чтобы проверить вдвоём — открой второе окно браузера **в режиме инкогнито**,
зайди на тот же адрес и введи **то же название комнаты**.

Остановить сервер: `Ctrl + C` в терминале.

---

## Шаг 3. Выложить в интернет, чтобы зашли друзья (бесплатно)

Пока сайт живёт только на твоём компьютере. Чтобы дать ссылку друзьям:

### Вариант А. Быстрый тест на один вечер

Установи туннель и покажи свой локальный сервер наружу:

```
npx localtunnel --port 3000
```

Получишь временную ссылку вида `https://xxx.loca.lt`. Она живёт, пока
включён твой компьютер и терминал. Для первых тестов — идеально.

### Вариант Б. Постоянный адрес

1. Заведи аккаунт на **GitHub** и залей туда папку `vmeste`
   (можно через приложение GitHub Desktop, без командной строки).
2. Зарегистрируйся на **Render.com** (бесплатный тариф).
3. New → Web Service → подключи свой репозиторий.
4. Настройки:
   - Build Command: `npm install`
   - Start Command: `npm start`
5. Через пару минут получишь адрес вида `https://vmeste.onrender.com`.

Важно: **HTTPS обязателен**. Без него браузер не даст доступ к микрофону
и демонстрации экрана. Render выдаёт HTTPS сам.

Минус бесплатного тарифа Render: если час никто не заходит, сервис «засыпает»
и первый заход после этого грузится ~30 секунд. Для тестов терпимо.

## Что уже умеет прототип

- Комнаты по названию, вход по ссылке `/r/название`
- Демонстрация экрана (в Chrome — со звуком вкладки)
- Голосовой чат с эхоподавлением
- Текстовый чат
- До 8 человек в комнате
- Работает в браузере на телефоне и компьютере, ничего ставить не надо

## Чего пока нет (сознательно)

- Регистрации и аккаунтов
- Постоянных серверов и каналов как в Discord
- Своего TURN-сервера — используется бесплатный публичный, он медленный
- Модерации

Это нормально. Задача прототипа — понять, будут ли люди этим пользоваться,
а не быть готовым продуктом.

---

## Как это устроено (в двух словах)

Видео и звук идут **напрямую между браузерами** участников (технология WebRTC).
Сервер только знакомит их друг с другом и передаёт текст чата.

Почему это важно для тебя: тяжёлый трафик не проходит через твой сервер,
поэтому хостинг стоит копейки даже при сотнях пользователей. Именно поэтому
mesh-схема — правильный старт при нулевом бюджете.

Ограничение: при 5+ участниках каждый отправляет своё видео каждому, и слабый
интернет не вытянет. Когда упрёшься в это — понадобится SFU-сервер (LiveKit,
mediasoup), и вот тогда пойдут расходы. Но это проблема успешного проекта.

## Известные шероховатости

- **Safari / iPhone**: демонстрация экрана в браузере не поддерживается —
  можно только смотреть и говорить. Это ограничение Apple, не кода.
- **Звук экрана**: захватывается в Chrome и Edge при выборе вкладки, если
  поставить галочку «Поделиться звуком вкладки». В Firefox — нет.
- **Публичный TURN** в конфиге медленный и общий. Для реального запуска
  подними свой `coturn` на дешёвом VPS (~200-300 ₽/мес) — это заметно
  улучшит соединение у людей на мобильном интернете.
